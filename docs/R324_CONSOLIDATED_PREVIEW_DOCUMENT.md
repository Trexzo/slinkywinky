The 385 recovered presentation callsites comprise 373 generic persistable records, ten dedicated controls (two modes and eight Piercing controls), and two action buttons which are deliberately not serialized. All seven value types are represented. This is not a native Slinky profile format and is not a live configuration or executable game feature.

The catalog fingerprint includes ordered module names/tabs, all widget metadata, numeric bounds/examples and branch visibility. A separate FNV-1a checksum detects accidental corruption, not adversarial forgery or origin authenticity. The parser enforces 64 KiB limit, version/catalog identity, canonical record order, exact consumption, valid booleans, bounds, masks, text, alias consistency and unique profile names. The document is independent of ClientSettings, module enabled flags, active key bindings and allow-input policy. Explicit MenuState restoration stages a copy, resets transient UI captures and pagination, then publishes by nonthrowing move. No production input route or native profile bridge invokes this new import. Save/load reuse R317 bounded reads and isolated atomic replacement; no default location or automatic persistence is introduced.
