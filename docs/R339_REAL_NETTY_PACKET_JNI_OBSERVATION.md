# R339 — Real 1.8.9 packet class observation, Netty FIFO and client-thread JNI source replay

**Purpose:** Bridge the actual Minecraft 1.8.9 packet transport into the same R335–338 read-only native source controllers without violating Netty thread affinity or retaining packet objects. Every packet passes to the original Minecraft network manager **exactly once and unchanged**. This provides real packet classification and channel ownership *observations* but DOES NOT reproduce original on-wire hold / cancel, delay or packet event timing.

## Implementation

- `SourcePacketReadOnlyQueue` (pure Java 8) copies only direction, kind, known entity ID, optional movement position, monotonic sequence and observation timestamp into a 256-element FIFO. It owns no game or packet references. Netty may call `offer` from its event loop. Only the captured Minecraft owner thread may `drain`. A full queue or invalid packet poisons the entire batch and forces source-session retirement; no partial event stream is trusted.
- `ForgeSourcePacketTap` uses the Forge-exposed `NetworkManager.channel()` on **singleplayer local client channel only**, installing one `ChannelDuplexHandler` before `packet_handler` on the channel event loop. It classifies real inbound `S19` status, `S06` health, `S29` sound, `S12` velocity and `S08` teleport, plus outbound `C03` movement, `C02` attack, `C0B` stop-sprinting and `C16/C0E/C0D` inventory actions. All other decoded `Packet` objects become `UNKNOWN`, preserving stream sequence. `S19` entity ID is deliberately **unknown** because it requires a world lookup unavailable on Netty. No world access, JNI, packet reference retention or game writes happen in the handler. Both `channelRead` and `write` ALWAYS forward the exact same packet and promise unchanged even if observation fails.
- `SourceWorldReadOnlyHost.observePackets` drains up to 128 primitive records per client tick, only after the real authenticated Java world/player tick and for exactly one bound channel queue per source world generation. It dispatches inbound Backtrack event2, outbound Lag Range event3, and specific outbound Inv Walk event23 through the real R335 `SourceRuntimePreview` JNI session; returns only counts/diagnostic receipts. Network channel replacement in the same source generation or an overflow fails closed. World replacement calls `retire`, and new-world source JNI controller state is reset by the generation transition.
- `ForgePreview` gates packet observation behind BOTH `-Dslinkywinky.r337NativeSourceTickReadOnly=true` and `-Dslinkywinky.r339PacketReadOnly=true`, plus manual F9 preview admission. The local Netty tap attaches asynchronously and is retired before the JNI controller on stop, disconnect or world swap.

## Important equivalence limits

Packet capture runs on the real Netty pipeline, but the read-only JNI decision occurs **after** the packet has already been forwarded and on the next admitted client tick. Thus native `held_ms=0` means a diagnostic unheld packet: it is **not** an observed hold duration, and the source has NO authority to apply the verdict. The source's original high-frequency event order and exact network or gameplay action parity are not proven. `S19` entity status is classified without claiming a target entity ID. The existing Backtrack reach eligibility still fails closed because original reach event admission is unknown. Inv Walk remains vanilla; no silent inventory packet queue has been enacted.

## Executable tests and packaging

`r339_java8_netty_packet_source_jni` compiles Java 8 and runs both standalone queue and **real JNI** packet replay tests, including cross-thread ingress, FIFO ordering, immutable receipt copies, bounded drain, poison-on-overflow, in/out JNI callbacks, native inventory packet callbacks, same-generation channel rejection, native session retirement, foreign-thread denial, game-world turnover and a new authenticated queue. The Forge 1.8.9 JDK8 workflow compiles the real `ForgeSourcePacketTap` and checks the produced JAR includes the queue, host receipt and tap; extra passive-flow contract asserts forwarding of the identical objects. Actual in-process Netty handler execution and in-game performance/fidelity acceptance are NOT yet established. PR #2 draft; PR #1 untouched; original decrypted assets not committed.
