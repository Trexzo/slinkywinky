# R317 — shared GUI preference persistence hardening

Base 29818fdd5f0e3790edafde47bcfbe77c6c849033. The two first-party GUI-only preference formats previously shared predictable target+".tmp" filenames. Concurrent saves or a preexisting temporary file could interfere with a save. Appearance parsing also read unbounded input; both noexcept save functions serialized before entering their exception handler.

Both now use a bounded stream reader and an independently created same-parent scratch directory, explicit stream-close checks, and a single destination replacement. Cleanup removes only its own contents and directory. The preexisting legacy .tmp file is never opened. Appearance input is capped at 4096 bytes; preview input retains its 512-byte cap. Embedded NULs are rejected. Serialization is now within the exception boundary. File paths remain native paths rather than roundtripping through narrow strings.

The CTest covers Unicode filenames, replacement, invalid save preservation, oversized and exact-bound input, embedded NUL rejection, failed replacement, empty paths, concurrent writers and scratch cleanup. Concurrent writer replacement can fail safely on platforms where the destination is temporarily unavailable; no guarantee that every concurrent save succeeds. No claim of crash durability, hostile-directory safety or cross-process locking. These are independently chosen first-party persistence safeguards, not recovered commercial source behavior. No changes to gameplay settings or callbacks, no new module implementation, no release. CI pending; local test execution not performed.
