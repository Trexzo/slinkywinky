## Goal

R212 created an explicit game-action owner and real Forge 1.8.9
movement-input and jumpTicks field adapter, but had not demonstrated
the writes in a real Minecraft process. Crucially, the existing
\`ForgePreview.onPlayerTick(PlayerTickEvent.END)\` applied the
No Slow decision too late to prove a gameplay effect.

R213 establishes a live **No Jump Delay cooldown-field acceptance**
in a real isolated Forge 1.8.9 singleplayer world, while preventing
the unverified late-tick **No Slow** input write from being presented
as an operational module.

## Original Minecraft 1.8.9 timing evidence

We inspected the authorized PC's cached, pinned Forge 1.8.9
stable_22 \`forgeBin\` class bytecode with real JDK8 \`javap\`.
In the developer-mapped \`EntityPlayerSP.onLivingUpdate()\` method:

- offset 325 calls \`movementInput.updatePlayerMoveState()\`;
- offsets 346–369 multiply \`moveStrafe\` and \`moveForward\`
  by vanilla \`0.2f\` while using an item;
- later game logic handles the movement state and calls super
  \`onLivingUpdate\` at offset 1125.

The previous \`TickEvent.PlayerTickEvent.END\` handler observes
these fields only after the normal player update has occurred.
A write at that late phase cannot be assumed to affect
movement consumed earlier in the same tick. The next vanilla
update may also overwrite the field.

The available Forge 1.8.9 stable_22 API has no independent
\`InputUpdateEvent\`. Its \`LivingUpdateEvent\` is generated by
\`ForgeHooks.onLivingUpdate\` from
\`EntityLivingBase.onUpdate\`, before the player override
updates and scales input, so it is **not** an appropriate
post-slowdown/pre-consumption hook either.

Conclusion: a game-side input hook with authenticated placement
**after** vanilla slowdown and **before** consumption is still
needed for No Slow. Current PlayerTickEvent.END is not a valid
source for claiming a functioning No Slow implementation.

## Code changes

### No Slow phase fence (Java 8)

File: \`java/dev/slinkywinky/OwnedModuleActions.java\`

The action input now explicitly carries
\`postSlowPreConsumeVerified\`. The backwards-compatible
constructor defaults this to **false**.

If a native No Slow policy produces an input-replacement
proposal but the caller has not asserted an authenticated
post-slow/pre-consume phase:

- the action owner does **not** write moveForward/moveStrafe;
- it reports \`noSlowBlockedByPhase=true\`;
- independently admitted No Jump Delay cooldown writes may
  still proceed;
- previously owned input values remain subject to conditional
  restoration (never overwrite changed physical input).

A future authenticated input-consumption hook may supply
\`true\`. R213 does **not** implement or certify that hook.
This boolean is a phase contract, not proof that an arbitrary
caller has been correctly instrumented.

\`ForgePreview.sampleOwnedModuleActions\` explicitly supplies
\`false\` because it runs at PlayerTickEvent.END. It also
throws if the late event somehow reports an actual No Slow
field write. The normal Forge preview remains read-only.

### Real No Jump Delay local acceptance

Files:
- \`experimental/forge189/src/main/java/dev/slinkywinky/forge/ForgePreview.java\`
- \`experimental/forge189/src/main/java/dev/slinkywinky/forge/ForgeModuleActionPort.java\`

New explicit JVM property:
\`-Dslinkywinky.r213LocalActionAcceptance=true\`

The property is only accepted if:
- the gameDir is under system TEMP with a
  \`slinkywinky-r213-independent-forge-\` instance name;
- the Java session username is exactly \`R213Offline\`;
- the observation/JNI test flag is also enabled;
- no R208/R209 automatic-world test is simultaneously active.

The R213 flag starts a **new local creative singleplayer
test world in the named temporary instance**. It auto-starts
the owner-thread native module control once the local player
appears.

To test the actual Minecraft private field with a reproducible
starting value, a separate **test-only fixture setter**
(\`ForgeModuleActionPort.setAcceptanceJumpTicks\`) writes the
private cooldown to 5 in this exact isolated world and no
other environment. That fixture setter is not part of the
normal \`OwnedModuleActions.Port\` and refuses all other
identities, game directories, phases or values.

At three player ticks, the test checks the real in-process
field immediately after the actual R212 game action owner:

1. No Jump Delay enabled: fixture 5 → action writes 0.
2. No Jump Delay disabled: fixture 5 → action does **not**
   write, field remains 5.
3. No Jump Delay re-enabled: fixture 5 → action writes 0 again.

The real native selection is toggled via Java/JNI
\`SprintObservationProbe.setModuleEnabled\`, not a local
mock flag. The test checks the real Forge
\`EntityLivingBase.jumpTicks\` field through the exact
development/SRG mapping established in R212.

**This tests real field writes but artificially supplies
the initial cooldown.** It does *not* prove repeated
physical jumps, key timing, movement packets or behavioral
equivalence to the original Slinky client.

## Fidelity and integration status

R213 is now a **real field-write acceptance** for the first
No Jump Delay action path, not complete natural jumping
gameplay acceptance. It simultaneously fixes the
over-optimistic No Slow timing assumption by refusing
late writes.

Remaining before claiming a full module:
- implement and verify a true post-vanilla-slow/pre-consumption
  input event/hook for No Slow;
- demonstrate repeated natural jumping from actual inputs
  with No Jump Delay enabled and disabled;
- verify focus loss, session world swaps, failed JNI, and
  unload ownership with real gameplay state;
- connect PR #1's actual interactive ClickGUI and ArrayList
  to acknowledged module state and applied actions;
- verify original candidate source behavior rather than only
  equivalent API names or field effects.

Sprint still returns data-only decisions.
Full Slinky GUI/ArrayList, injection lifecycle and other module
callbacks remain separate unfinished work.

The original native callback reconstruction count has not
changed: 66 mapped module descriptors, 171 candidate callback
subscriptions, 16 offline module policies, 22 callbacks with
offline implementations, **149 unimplemented**.
