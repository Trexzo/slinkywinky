This is the **first production Forge render-phase call to the existing source-shaped Timer Range AABB prediction** through Java 8 + JNI + the same C++ source `ModuleExecutionBridge` state.

The new `SourceWorldReadOnlyHost.RenderPort` and immutable `RenderFrame` accept a strict 20-double snapshot, bounded render dt and 0..1 partial tick; the JNI frame is admitted only following a previously accepted native client/world tick, on the same Java owner thread, same original Java world/player object identities, and same native generation/tick. A null crosshair target is skipped, never replaced by an invented target. Replaced worlds invalidate retained receipts, and midread substitutions or invalid data retire the native source session. Host `close()` is idempotent on the original owner thread.

It rejects non-local worlds and foreign render threads. **Original target interpolation countdown and exact movement factor are not recovered**, so the diagnostic currently supplies `0` countdown and `0.1` movement factor and documents those assumptions rather than asserting parity.

The existing `ForgePreview.onRenderFrame` now calls this **read-only** source frame path before the unrelated HUD decision simulator, using a bounded monotonic delta. It never applies the proposed timer-speed, packet gate, input, attack click or elapsed-tick modification. This is an observed prediction, not functional Timer Range gameplay.
