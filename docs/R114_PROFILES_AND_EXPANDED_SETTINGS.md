Branch: `reconstruction/r1-core-fidelity` · Draft PR #1 · Native injectable client (not Forge).

## Original Slinky visual sources

The official Slinky documentation provides close-up screenshots:

- [Profiles screenshot](https://docs.slinky.gg/_astro/profiles.BVi9pNfi_ZoANip.webp): two-column, dark rounded cards; profile title/bind at top-left; muted status text; four compact action icons at top-right (save/upload, load/download, folder, delete).
- [Collapsed module](https://docs.slinky.gg/_astro/collapsed.BfdVLPGh_Z25HoFu.webp) and [expanded module](https://docs.slinky.gg/_astro/expanded.CvnwaSZe_1K3k5y.webp): an ordinary module header followed by a section caption, a left-aligned setting name and an outlined right-aligned value selector.
- [GUI settings](https://docs.slinky.gg/_astro/mod-gui.DgAVCIRV_Zlzw8j.webp): separate GUI settings for scale, accent color and input-while-open; Slinky documents that these remain independent of loaded profiles.
- [Original menu navigation](https://docs.slinky.gg/_astro/nav.hxxCX4fS_Z1ckBvz.webp): the reference screenshot shows six tabs. R114 deliberately leaves the prior project's seven-tab catalog intact (including Block) rather than silently dropping module access. This visual mismatch remains for a future catalog-preserving reconciliation.

This is an original, first-party rendering implementation guided by visual references, not redistribution of Slinky's screenshots, code, fonts, icons or original client assets.

## Implemented

1. `MenuProfileCard` is a bounded immutable, **presentation-only** part of the existing `MenuRenderFrame`. A regular `MenuRenderSession` supplies only its actual first-party `Default` profile card. Nothing reads user profile folders or asserts that other profiles are installed.
2. `menu_profile_preview.hpp` verifies ASCII-only limited names/labels, unique profile names, exactly one first default card, bounded card count, safe card bounds and no profile data on ordinary module tabs. Invalid display snapshots are rejected by **both** the GL renderer and native hit tester before further action.
3. `menu_visual_geometry.hpp` provides responsive one/two-column card geometry, compact heights and larger source-style expanded setting regions. Profiles in an ordinary 676px logical panel render two columns; narrower panels use one.
4. `windows_menu_gl11.cpp` draws Slinky-style dark rounded profile cards, gray/colored keybind badges, muted descriptions, and four independently hand-drawn action glyphs with red deletion accent. **Glyphs are deliberately inert.** There are no save/load/delete, folder-opening, file enumeration or gameplay calls in this work.
5. Expanded modules now use grouped captions (`Main`, or `In-game` for Auto Clicker) and a real caption/value split taken only from the first-party `MenuProfileBridge::primary` numeric snapshot. Example: `Clicks/sec` on the left, `12.00` in an outlined pill on the right. This does **not** pretend that the original commercial Auto Clicker's `Click pattern: Jitter` setting has been implemented.
6. Source tests assert no accepted profile-card mouse actions; forging an invalid profile name/path, duplicate, first-default marker, overly long status or too many cards refuses drawing. A forged profile on an ordinary Combat frame refuses clicks. Additional rendering cases prove GL state restoration and original scoped WGL admission.
