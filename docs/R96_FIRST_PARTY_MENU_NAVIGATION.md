# R96 — first-party ClickGUI navigation model and focused-row GL11 evidence

**Status:** source-only/navigation-in-standalone-preview implemented on the unmerged draft `reconstruction/r1-core-fidelity` PR. Native Windows x64 MSVC Release and Java 8/JNI/Attach fixtures: **26/26 CTest PASS**. Original Minecraft in-game keyboard/mouse integration is **NOT** claimed or enabled.

## Scope

R96 closes the gap between the R94/R95 *visibility* proof and a usable local UI model, but deliberately does not cross the currently unaccepted game-input boundary. R95's separate original-game `Insert` attempt was denied by Windows foreground checks; this refusal is **not circumvented**.

- `MenuNavigation` is a new native C++17 model in `include/slinkywinky/menu_navigation.hpp` and `src/menu_navigation.cpp`. It is **bound to the construction thread and the exact `MenuState`/`MenuProfileBridge` pair**. It never reads Windows keys, Minecraft memory, Java methods or game packets.
- Explicit model actions: `NextTab`, `PreviousTab`, `NextRow`, `PreviousRow`, `ExpandFocused`, `ToggleFocusedPreview`, `IncreaseSetting` and `DecreaseSetting`. The five module tabs and informational Profiles tab are keyboard navigable, but the Unload tab and invalid Count sentinel **cannot be selected** by this model. Focus wraps between permitted tabs but not beyond the first/last row within a tab.
- The selected **catalog index** stays coherent with the eight visible rows as the page auto-scrolls, including the 17-row Combat tab. Changing a tab resets the selected row to its first visible catalog entry. Mouse selection is constrained to a row actually visible on the current page; stale off-screen indices are denied. Moving from a module tab into Profiles clears row focus.
- The 58 **NOT IMPLEMENTED** module entries remain view-only. Toggle/expand/setting actions against these entries are refused. Only the seven existing first-party profile-bound module settings can change; these are **local configuration preview state**, not game module activation or live combat behavior. A numeric adjustment is allowed only for an implemented, visible and expanded row and must pass existing strict settings-schema validation.
- `MenuRenderSession::next(menu,profile,navigation)` validates exact owner menu/profile/controller identity before accepting a sequence. The original two-argument `next(menu,profile)` entrypoint and original `MenuRenderFrame` binary layout remain unchanged; the focused catalog index is copied into a separate `std::optional<std::size_t>` value at the owner-thread GL draw boundary. The original three-argument `WglMenuOverlayHost::draw(menu,profile,mode)` and legacy two-argument forms remain available, with a distinct opt-in focus overload. No mutable gameplay pointer enters the rendered frame.
- The first-party GL11 renderer has a distinct fifth argument for optional focus and validates that a focused item actually appears in the current frame. Focus is indicated with a thin accent line and left-edge stroke inside the existing panel. Invalid or off-page indices are refused **before modifying GL state**. If the focused value is absent, the renderer follows the exact previous unhighlighted appearance.
- `examples/windows_gl11_menu_preview.cpp` is the **standalone Windows demo executable**, not injected into Minecraft. It now uses its own native `WM_KEYDOWN` and `WM_LBUTTONDOWN` handlers only: `Left/Right` or `Tab` change tab, `Up/Down` move the row, `Enter` expands, `Space` changes a local preview flag, `+/-` adjusts local numeric values; existing 1–6 tab shortcuts, native appearance controls and profile save/load remain available. Mouse wheel scroll updates focus and clicking a visible module focuses that row. These controls are never installed into Minecraft and never send game input.

## Evidence and negative controls

- The new platform-neutral `native_menu_navigation_ownership` CTest verifies 17-row automatic scroll, first/last row refusal, six-tab wrapping without selecting Unload, ownership of a specific menu/profile pair, visible-row-only mouse focus, unsupported-module refusal, numeric update only after expansion, and foreign-thread denial without changing state.
- Existing `native_menu_render_lifecycle` covers earlier snapshot/sequence preservation and re-admission. R96 supplements this with refusal of a foreign menu-navigation owner and checks for lossless value snapshots between row selections.
- Existing `isolated_wgl_menu_state_restore` adds a focused row **actual OpenGL pixel readback**: the focus accent appears on row one, moves to row two, and disappears from row one after a redraw. An unsupported/off-page focused index is refused before rendering. Production host rendering and the full GL model/projection/texture, attrib/client-attrib, viewport and color-state restoration remain verified on the disposable Win32 WGL fixture.
- **Full local Windows Release:** 26/26 CTest PASS, including Java 8 Attach/JNI/WGL and native menu model, with no Minecraft JVM needed. The native source also builds in the same Windows project configuration as the injector and standalone preview. GitHub Actions must be independently checked at the final head after documentation commits; don't infer CI from the local results.

## Remaining acceptance before in-game ClickGUI

R96 does not intercept Minecraft keyboard/mouse or inject OS input. The original game still only has the R94 limited **visibility** overlay; the new navigable preview is not wired into that in-game JNI path. A safe later integration must solve foreground/focus and keybinding-collision checks, define an explicit input-capture policy that does not send accidental actions to Minecraft, guarantee owner-thread-only navigation/GL, and certify source-pinned original-bytecode restoration and bounded unload when the GUI closes. No FPS, world visualization or actual gameplay module acceptance is inferred from these tests.

Keep PR #1 draft/unmerged; gameplay/combat modules remain disabled.
