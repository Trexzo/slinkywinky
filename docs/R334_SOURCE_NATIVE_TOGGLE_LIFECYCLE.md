# R334 — final two original-table callbacks for the R329–R333 quartet

R334 uses the actual `EventReplay.apply()` notification path (event slot 5) for the remaining two original callback subscriptions of **Timer Range** and **Inv Walk**, both signed priority 0. This is not a separate event manager.

Previously `ModuleExecutionBridge`'s observer intentionally ignored events delivered while no `ExecutionFrame` was active, which includes notifications generated by the native `request()/apply()` replay. R334 adds an explicit, per-module allowlist only for the two new source lifecycle callback owners. Other modules' notification semantics and callback order remain unchanged.

- **Timer Range e5 disable:** calls source model `disable()` to clear frozen packet hold, timer-speed zero and use-key latch. Returns a single-consumer `TimerRangeProposal` restore **receipt** to the caller. Force-stop also emits a value-only restore receipt.
- **Inv Walk e5 disable:** captures the count of offline queued clicks before resetting the module state. Emits an explicit `InvWalkSourceCleanupReceipt` saying a future real packet owner must decide how to reconcile that count. **No queued JNI object is stored or transmitted**, and no click is silently claimed delivered.
- **Forged/manual event5 replay frames cannot trigger teardown.** Source lifecycle callbacks only take effect during the `EventReplay.apply()` delivery after a real module state request. Event ownership checks require target module ID, disabled state, source descriptor name/category/full slot+priority signature, and an already attached tick model.
- Rollback and stop apply the existing fail-closed behavior. Cleanup receipts never run game I/O, change physical key states, or create packet objects.

New `r334_source_toggle_cleanup_lifecycle` tests cover real apply() disable, synthetic event rejection, paired disable in the same batch, exact timer restore, explicit inventory queued-click reconciliation, one-time consumption, re-enable without stale packet state and forced-stop recovery.

This brings the **four R329 candidate source modules** to **15/15 registration-slot callbacks with offline C++ bindings**, while still lacking the original runtime's actual callback scheduling, source JNI object ownership and 1:1 in-game fidelity. The other 62 registered modules remain partially reconstructed or experimental, not complete or playable. PR #1 untouched, PR #2 draft/unmerged.
